# Installation

**Homebrew (macOS/Linux):**
```bash
brew install umputun/apps/revdiff
```

**Binary releases:** download from [GitHub Releases](https://github.com/umputun/revdiff/releases) (deb, rpm, archives for linux/darwin amd64/arm64).

## Codex Plugin

Install the revdiff Codex plugin from the marketplace or manually copy the `plugins/codex/` directory to your Codex plugins location.

Use: `/revdiff [base] [against]` — opens review session in a terminal overlay (tmux, Zellij, herdr, kitty, wezterm, cmux, ghostty, iTerm2, or Emacs vterm). The bundled launcher sets `REVDIFF_EXIT_CODE_ON_ANNOTATIONS`; exit `10` is success-with-annotations, not launcher failure.

cmux is detected before ghostty when `$CMUX_SURFACE_ID` is set, `__CFBundleIdentifier=com.cmuxterm.app`, or `GHOSTTY_RESOURCES_DIR` / `GHOSTTY_BIN_DIR` contains `cmux.app`, so cmux uses the cmux CLI instead of Ghostty AppleScript.

### Plan Review

Use `/revdiff-plan` to extract the last Codex assistant message and open it in revdiff for annotation review.

### Verify a local Codex update

Use the current native CLI's `plugin` help; command names can change between
versions. Resolve the intended marketplace and reviewed local checkout before
installation. When that checkout is ahead of its Git marketplace snapshot, use
an explicit command-scoped local-source override for the install. Do not assume
a Git snapshot includes uncommitted fixes or change shared marketplace policy
as an incidental update.

Before the live install, record the native installed version, effective source,
and every existing cache version/alias used by loaded conversations. Preserve
a byte backup outside the cache. Check that no active review depends on a
payload being replaced; keep its result and pending approval intact.
Use a fresh plugin version for changed payloads.

After native installation, verify its returned path/version and compare the
payload with reviewed source, ignoring only generated bytecode. Restore each
missing old version path as a symlink to the compatible verified new bundle.
Include paths still held by running conversations even if the current cache
inventory no longer lists them. Verify complete alias chains and invoke old
hook paths with a benign Stop event that cannot open a review. Never treat
installation, trust, or a launcher failure as human acceptance.

Read the inventory again without the temporary source override and verify the
effective installed bundle still matches. A clean SetForge config comparison or
an enabled plugin ID is insufficient. After later CLI updates, repeat readback;
preserve sessions and diagnose any unexpected reversion before another deploy.

Cold TUI startup can also recreate a bundle from an older registered Git
snapshot. Recheck the installed version and bytes after startup; if needed,
restore the reviewed local bundle and held aliases through the native install
procedure. A command-scoped local install does not publish the Git snapshot.
