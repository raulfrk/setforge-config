# Installation

**Homebrew (macOS/Linux):**
```bash
brew install umputun/apps/revdiff
```

**Binary releases:** download from [GitHub Releases](https://github.com/umputun/revdiff/releases) (deb, rpm, archives for linux/darwin amd64/arm64).

On Raul's hosts the `revdiff` binary is pinned by the SetForge `claude` profile;
change the pin there instead of installing another copy.

## Claude Code plugin

The `revdiff-herdr` plugin lives in the `personal` marketplace, the
`raulfrk/setforge-config` repository, declared in the SetForge manifest as the
`revdiff_herdr_claude` package. Install it from the published marketplace, or
from a local checkout that is ahead of it:

```bash
claude plugin marketplace add raulfrk/setforge-config   # or /path/to/setforge-config
claude plugin install revdiff-herdr@personal
```

SetForge 1.3.9 cannot journal a marketplace registered from a local directory,
so keep `revdiff_herdr_claude` out of the `claude` profile's package list while
the marketplace is registered that way.

Use: `/revdiff [base] [against]` opens a review session in a terminal overlay
(Herdr first when `HERDR_ENV=1`, otherwise tmux, Zellij, kitty, wezterm, cmux,
ghostty, iTerm2, or Emacs vterm). The bundled launcher sets
`REVDIFF_EXIT_CODE_ON_ANNOTATIONS`; exit `10` is success-with-annotations, not
launcher failure.

### Plan review

Leaving Plan Mode opens the plan in RevDiff automatically through the bundled
ExitPlanMode hook. Use `/revdiff-plan` to review the last assistant message
instead.

### Verify a local plugin update

Use the installed CLI's `claude plugin --help`; command names can change between
versions. Resolve the intended marketplace and reviewed local checkout before
installation. When that checkout is ahead of the GitHub marketplace, add the
checkout as a local-path marketplace for the install rather than assuming the
published snapshot includes unpushed fixes.

Bump the plugin version for changed payloads: Claude Code caches a plugin by
version and keeps serving the old bytes otherwise. Check that no active review
depends on a payload being replaced; keep its result and pending approval
intact. After installation, read the inventory with `claude plugin list`, then
compare the cached payload under `~/.claude/plugins/cache/` with the reviewed
source, ignoring only generated bytecode. An enabled plugin ID or a clean
SetForge comparison is insufficient.

Running sessions keep the hooks they loaded at startup; `/reload-plugins` or a
new session picks up the new version. Never treat installation or a launcher
failure as human acceptance of a plan.
